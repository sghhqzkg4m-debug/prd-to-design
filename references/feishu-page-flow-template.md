# 飞书页面流程模板

一个 Case 对应一张飞书原生白板。模板复用「任务边界 → 可选的阶段分组 → 角色／平台泳道 → 页面步骤 → 主路径与交接 → 底部异常返回 → 交接与恢复说明」的表达关系。它解释从哪个页面完成什么判断、怎样交接或返回；用户旅程另用 `user-journey` 的模板解释跨角色业务任务，不用同一张图重复两者。

## 数据与生成

从 `../assets/feishu-page-flow-template.json` 复制数据结构，按 Case 填写后运行：

```bash
python3 scripts/render_feishu_page_flow.py flows.json 0 flow.svg
```

输入可为一个 Case 对象或 Case 数组，数组第二个 Case 的索引为 `1`。字段：

- `title`、`boundary`：读者可见的任务名称、起点与真实完成标识；建连成功、创建成功不能替代真实使用结果。
- `phases`（可选）：`title`、`result`、`count`；各 `count` 之和等于步骤数。阶段只是分组表头，不画悬空推进箭头。
- `roles`：`name`、可选 `note`；每个参与方一条泳道。
- `steps`：顺序排列，填写唯一 `id`、执行 `role`（从 0 起）、`page`（平台名称－具体页面）、`title`、`detail`、可选 `feedback`。页面名未核查时在 `page` 明写待核查。一个步骤只放在其执行角色的泳道内。
- `links`：`from`、`to`、`kind`（`main` 或 `return`）、`label`。主路径连接相邻步骤，跨角色的转折位于节点间留白；`return` 指向较早步骤，走全部角色泳道下方的独立虚线。节点内就地修正只写在 `feedback`，不画自环。

步骤、阶段和角色数由 Case 决定；示例 JSON 的占位数量不是配额。并行分叉、汇合或跨多列跳转若无法用相邻步骤表达，先整理条件与交付物，再按本模板的视觉语义手工布局，不把真实分支错误改写为线性路径。

## 检查

- 每条线能从实际触发节点追到目标节点；交接标明交付物或条件，异常标明原因、用户可执行动作和返回位置。
- 连线不穿过卡片与文字，同排走水平线，跨泳道在列间转弯，异常走底部；没有业务依赖就不补线。
- 白板导入后导出飞书实际预览，检查文字裁切、节点与箭头位置，并确认节点和连接线可编辑。已有非空白板按飞书画板编辑流程保护原内容；不要把渲染成功当作写入完成。
- JSON 与 HTML、正文使用同一组 Case 结论；图的阶段和步骤不得从其他需求照搬。
