# 飞书正文组件模板

进入 `feishu-delivery` 时，在第一次写入正文前读取本模板。模板固定**阅读任务 → 内容槽位 → 原生组件 → 核对方式**，不固定某一需求的句子、Case 数、表格行数或组件配额。用户给定的文档结构和既有组件优先；短内容用短段落即可。

| 内容槽位 | 读者要完成的事 | 默认组件 | 适用与裁剪 |
|---|---|---|---|
| 业务背景 | 理解为什么做 | 两个以内短段落 | 缺可靠现状证据时就地注明证据状态，不造“改版前” |
| 业务目标 | 快速抓住业务结果 | 一条引用／高亮块 | 目标有多个独立结果时，可在块内分两短段；不另造同义摘要 |
| 版本边界／关键冲突 | 避免误读承诺范围 | 警示高亮块 | 仅有明确冲突或高影响未决边界时使用；普通非范围用短段 |
| JOB | 定位用户与任务 | 引用块或强调段 | 角色准备与交接另用相邻短段；不把全段塞入卡片 |
| Case 起点与完成标识 | 知道任务何时开始、何时算完成 | 两条短段 | 交接动作由旅程承载，不在这里重述整条路径 |
| Case 体验目标 | 扫描预期业务与体验进步 | 一条目标高亮块 | 每个 Case 一条；设计重点、设计目标紧随其后用短段，不堆叠同义卡片 |
| 竞品取舍 | 横向比较议题、证据边界与我方判断 | 原生表格 | 触发研究且多议题时使用；单一短结论用段落 |
| 本期范围 | 对照用户任务与设计覆盖 | 原生双列表格 | 多任务时使用；单项范围用短段，非范围另述 |
| 权限、状态与跨步骤约束 | 按对象或环节查规则 | 原生表格 | 多字段／多角色才用；高风险未决条件另用短警示块 |
| 待决策 | 比较问题与当前处理 | 原生双列表格 | 两项以上使用；单一问题用短段，不藏在折叠区 |
| 设计验证 | 对照任务与观察结果 | 原生双列表格 | 多 Case 使用；原型与实机验证能力边界置于表后短段 |

## 原生 XML 片段

这些片段只展示结构。替换方括号内容，删去不适用的组件；不要把占位符、模板说明或固定示例行写入成品。

```xml
<p>[业务背景的一条事实]</p><p>[角色责任与证据边界]</p>
<callout emoji="🎯" background-color="light-blue" border-color="blue"><p><b>业务目标</b>　[业务结果]</p></callout>
<callout emoji="⚠️" background-color="light-yellow" border-color="yellow"><p><b>版本边界</b>　[冲突与当前处理]</p></callout>
<blockquote><p><b>JOB</b>　[用户、场景、任务与进步]</p></blockquote>
<p><b>起点</b>　[触发与前提]</p><p><b>完成标识</b>　[可观察的真实结果]</p>
<callout emoji="🎯" background-color="light-green" border-color="green"><p><b>体验目标</b>　[业务进步与体验变化]</p></callout>
<p><b>设计重点</b>　[关键取舍]</p><p><b>设计目标</b>　[策略如何支持体验改善]</p>
<table><thead><tr><th><p>[比较维度]</p></th><th><p>[结论与处理]</p></th></tr></thead><tbody><tr><td><p>[当前事项]</p></td><td><p>[有证据的内容]</p></td></tr></tbody></table>
```

## 写入与回读

先为本次授权范围填 [飞书组件编排清单模板](../assets/feishu-delivery-plan.template.json)；每个内容项写明阅读任务、组件、位置和预期可检索的文本标记。每个 Case 分别列体验目标、旅程、页面流程，以及是否有页面图；没有触发的组件写 `omit` 与原因，不能静默缺席。运行 `python3 scripts/validate_feishu_delivery.py plan <清单.json>`，通过后才开始首个正文写入。

写入时直接创建选定的标题、短段、表格和画板；不要先铺纯段落再补组件。写入后用 `lark-cli docs +fetch --detail with-ids` 等方式回读飞书正文 XML，保留完整 JSON 响应到项目目录的 `feishu-fetch.json`，运行 `python3 scripts/validate_feishu_delivery.py verify <清单.json> <fetch.json>` 检查已规划的组件类型和文本位置；`node scripts/validate-artifacts.mjs <项目目录> --feishu` 也会调用这一检查。画板仍须查询原生节点和查看实际预览，页面图检查尺寸。校验器发现缺项时继续补齐，无法补齐则标记部分交付。
