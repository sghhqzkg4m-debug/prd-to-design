# 平台核查路由

涉及深信服产品时，先在 [深信服设计平台](https://ui.sangfor.com.cn/projects) 定位对应产品线，再检查适用的模板、工作区和现有页面。产品线模板可提供视觉与页面框架起点；现有工作区或真实页面才可作为具体导航、组件和交互行为的证据。不得把某一产品线的框架直接套到其他产品线，也不得将模板中的示例页面当作已上线能力。用户另外提供的页面、截图或代码也应纳入核查。

## 需要核查的内容

- 产品定位、主要角色和当前工作上下文。
- 导航层级、现有入口和相关页面。
- 页面壳层、内容宽度、密度和滚动方式。
- 表格、筛选、抽屉、对话框、分页、空状态和错误反馈模式。
- 若能读取工作区代码，再核查真实路由、组件库、Token、权限模式和请求层；仅能看到平台界面时，不推断这些实现细节。

## 输出分类

| 分类 | 含义 |
|---|---|
| 必须继承 | 全局壳层、导航规范、品牌 Token 等不可破坏的基线 |
| 优先复用 | 已成熟且适合当前任务的组件和交互模式 |
| 可以改进 | 已有模式存在明确体验问题，且改动不破坏平台一致性 |
| 已知设计债 | 识别但不在当前需求中扩大处理 |
| 不适用 | 与当前 Job 或对象无关，不作为设计输入 |

无法访问页面时使用用户截图、代码或说明继续分析，并明确证据缺口。不要绕过登录、安全限制或凭截图编造精确组件 API。
