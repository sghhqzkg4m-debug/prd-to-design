# 版本变化对比图

## 生成判断

只有上一版本的任务路径、对象关系或交付物有可核查来源，且本期确有影响用户任务的变化时生成。先提取旧版事实、本期已确认需求、设计假设和待验证约束；不得把候选方案画成已实现能力。缺少可靠旧版资料时，展示已知断点与目标方案，明确证据边界，不使用虚构的“旧版流程”。

## 固定信息框架

1. 写清同一个 JOB 或 Case 的任务与比较范围，并标明旧版和本期的性质。
2. 只选真实发生变化的维度：参与角色与交接、入口与操作、对象及归属、交付物、反馈与完成结果。两侧使用一致的比较单位。
3. 用图形和连线呈现关系或路径；文字只作为节点标签。用“保留／新增／替代／删减”标记变化，避免把两栏文字卡片冒充对比图。
4. 图下用一句话说明变化如何支持体验目标，并就地标出旧版证据、本期假设及待验证条件。
5. 图中节点、阶段和分支数量由任务决定，不套用模板示例的三阶段或固定角色数。

## 图形选择与位置

- 对象数量、归属或连接方式变化：使用前后关系／拓扑图。多个 Case 共用的能力变化放在 JOB 下方、Case 之前。
- 用户操作顺序、分支或恢复路径变化：使用前后双轨流程图。仅涉及单个 Case 时放在该 Case 目标之后。
- 交付物或跨角色交接变化：使用带角色泳道和交接物的前后图；复杂任务仍保留完整旅程，对比图只作导读。

版式按读者最需要比较的关系选择，不写死图形模板。当前后两侧都是少量对象、主变化是“一对一／一对多”等关系时，优先采用左右并列的完整场景图：左侧现状、右侧目标，中间一个方向箭头；两侧各自画完整连接关系，并在对应位置用颜色、虚线或阻断符号突出变化。这种版式比把对象拆成上下两排更容易先读懂整体。若对象很多、需要逐项追踪对应关系，可改用上下对齐或分层拓扑；若重点是时间顺序、分支和恢复，则改用双轨流程；跨角色交接以泳道为主。选择后检查图在常见桌面宽度下是否能一眼辨认主变化，节点和说明是否无需来回寻找。

HTML 图形使用自包含 SVG 或等价可访问组件，窄屏可横向滚动或重排，保留标题与文本替代说明。飞书使用原生可编辑白板。生成后检查节点与连线是否对应需求证据、标签是否可读、旧版事实与目标方案是否明确区分。

## 连线语义与视觉检查

- 每条业务关系必须有明确的起点、终点和方向。线从节点边缘的连接点出发并抵达目标节点边缘；箭头落在目标节点前，不悬空、不穿过卡片或文字。没有关系的两节点不画线。
- “受阻／不可接入”也要指明被阻断的对象关系：从来源节点到目标节点画灰色虚线，在该虚线的末段放叉号或阻断符号，并配极短原因标签。孤立的叉号不能代替连线。
- “前后对应”与“业务连接”使用不同线型。跨版本对应可用细虚线或变化标签；同一版本内真实连接用实线。不要让对应线看起来像新增业务连接，也不要把目标方案的连线画进现状区域。
- 多条线汇聚或分叉时，优先从同一源节点分别连向各目标节点；如需总线或折线，转折点放在节点间留白，避免线段贴边、交叉或与标签重叠。
- 交付前实际渲染桌面与窄屏，逐条沿线追踪起终点并检查箭头、阻断标记及文字遮挡。若线的含义需靠正文才能猜出，应重画或补在线旁的短标签。
